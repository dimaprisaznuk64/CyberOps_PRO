# Точні піни, а не `==X.Y.*`.
#
# `==0.141.*` — валідний запис PEP 440, але він фіксує лише мажорну й мінорну
# частину: наступний `pip install -r` міг зняти 0.141.2 і створити образ,
# який ніхто не відтворить. Один `bcrypt` тут був точним, решта 28 — ні.
#
# Значення нижче — це рівно те, що встановлено і на чому пройшли 254 тести,
# CI та обидва стенди. Тобто пін — це не «остання доступна», а «перевірена».
#
# Чому лише прямі залежності: транзитивні (click, h11, anyio, certifi) лишаються
# плаваючими, тож це ще не повний lock. Повний lock з хешами (`pip-compile
# --generate-hashes`) — окрема робота: він ламається на кожному безпечному
# оновленні й вимагає процесу, а не разового коміту.
#
# Як піднімати версію: bump-minor (0.141.1 -> 0.142.0) — шукати CVE;
# bump-patch (0.141.1 -> 0.141.2) — звичайне виправлення. Оновлення
# без зміни цього файлу неможливе, і це навмисно.
